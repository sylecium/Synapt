# Rapport d'audit de code - Synapt (2026-09-17)

## 1. Cartographie

- **Architecture** : Application desktop Linux locale monoposte combinant un backend Rust (Tauri 2) et une interface Svelte 5 / SvelteKit SPA (`adapter-static`, sans SSR).
- **Backend Rust** : Runtime Tauri 2 (`src-tauri/src/lib.rs`), commandes IPC (`commands.rs`), persistance SQLite locale via rusqlite embarqué (`db.rs`, `repo.rs`), logique financière et génération PDF printpdf (`honoraires.rs`, `honoraires_pdf.rs`), intégrations externes HTTPS via reqwest (`stripe.rs`, `ntfy.rs`).
- **Frontend Web** : Bun, TypeScript, Vite, Tailwind CSS 4, shadcn-svelte, Bits UI, éditeur de texte riche Tiptap (`src/routes/` et `src/lib/components/`).
- **Gestionnaire de paquets** : Bun pour le frontend (`package.json`, `bun.lock`), Cargo pour le backend (`src-tauri/Cargo.toml`).
- **Points d'entrée** : `src-tauri/src/main.rs` (binaire natif), `src/routes/+layout.svelte` (shell UI avec sidebar et bandeau de mise à jour).
- **CI / Distribution** : GitHub Actions (`.github/workflows/release.yml`) produisant un paquet Debian (`.deb`) signé pour Debian 13 avec auto-mise à jour via `tauri-plugin-updater`.

## 2. Priorisation

Les 20 % du code portant 80 % des risques techniques, métiers et légaux sont :
1. **Accès base de données et concurrence** (`db.rs`, `commands.rs`, `repo.rs`) : gestion des connexions, verrouillage SQLite, intégrité transactionnelle.
2. **Logique financière et génération PDF** (`honoraires.rs`, `honoraires_pdf.rs`, `tva.rs`) : numérotation séquentielle stricte, calculs de TVA, respect des mentions légales et intégrité des fichiers.
3. **Flux réseau et gestion des secrets** (`settings.rs`, `stripe.rs`, `ntfy.rs`) : manipulation des tokens, masquage des clés et communication sortante.
4. **Cycle de vie des données côté client** (`debouncedNoteSave.ts`, `RdvPanel.svelte`, `notes/+page.svelte`) : persistance asynchrone des notes cliniques et prévention des pertes de saisie.

## 3. Analyse approfondie et fiches d'anomalies

### Problème 1 : Panique Rust potentielle sur découpage de chaîne UTF-8
- **Sévérité** : Majeur
- **Emplacement** : `src-tauri/src/settings.rs:184`
- **Constat** : La fonction `mask_secret` découpe les 4 derniers octets d'une chaîne via `&s[s.len() - 4..]` sans vérifier les frontières de points de code UTF-8.
- **Impact** : Si un token ntfy ou une chaîne contient un caractère multi-octets dans ses 4 derniers octets, l'exécution déclenche un `panic` immédiat qui fait crasher l'application.
- **Correction proposée** :
```rust
pub fn mask_secret(s: &str) -> (bool, String) {
    if s.is_empty() {
        return (false, String::new());
    }
    let chars: Vec<char> = s.chars().collect();
    let last4: String = if chars.len() <= 4 {
        chars.into_iter().collect()
    } else {
        chars[chars.len() - 4..].iter().collect()
    };
    (true, last4)
}
```
- **Effort** : S

### Problème 2 : Tempête de requêtes N+1 / N*M à l'affichage des RDV
- **Sévérité** : Majeur
- **Emplacement** : `src/lib/components/RdvContextMenu.svelte:60-83` et `src/lib/honoraireRdv.ts:4-18`
- **Constat** : Chaque instance de `RdvContextMenu` (montée sur chaque cellule de l'agenda et chaque élément de liste du dashboard) exécute un `$effect` au chargement. Ce dernier appelle `findHonoraireEmisForRdv(clientId, id)`, qui liste l'ensemble des honoraires du client via IPC, puis interroge individuellement chaque note d'honoraires pour chercher une correspondance de ligne.
- **Impact** : Pour 25 rendez-vous visibles dans la semaine, entre 50 et 200 appels IPC et requêtes SQLite sont déclenchés simultanément lors du simple affichage de la grille. Cela sature le pont IPC et provoque des saccades.
- **Correction proposée** :
  1. Charger l'existence d'une note d'honoraires à la demande (lazy-load lors de l'ouverture effective du menu contextuel ou du panneau de détail).
  2. Alternativement, inclure directement un booléen `a_honoraire` ou `honoraire_id` dans la requête SQL `RDV_SELECT` via une jointure gauche sur `honoraire_lignes`.
- **Effort** : M

### Problème 3 : Connexion SQLite recréée et migrations exécutées à chaque commande IPC
- **Sévérité** : Majeur
- **Emplacement** : `src-tauri/src/commands.rs:46-55` et `src-tauri/src/db.rs:208-217`
- **Constat** : La fonction utilitaire `with_db` ouvre à nouveau le fichier SQLite sur le disque (`open_file(&path)`), prend un verrou `DB_MUTEX`, puis invoque `migrate(&conn)` à chaque commande IPC. `migrate` lance un batch DDL complet et exécute 11 fois `PRAGMA table_info`.
- **Impact** : Des dizaines d'accès disque superflus et d'analyses de métadonnées SQLite se produisent même pour des opérations en lecture seule ou lors de la frappe dans l'éditeur de notes (debounce à 400 ms).
- **Correction proposée** :
  - Conserver une connexion SQLite unique dans l'état de l'application via `tauri::State<Mutex<Connection>>`.
  - N'exécuter `migrate` qu'une seule et unique fois lors de la phase `setup` de l'application dans `lib.rs`.
- **Effort** : M

### Problème 4 : Absence d'indexation SQL et filtrage temporel effectué en mémoire
- **Sévérité** : Majeur
- **Emplacement** : `src-tauri/src/db.rs:34-97` et `src-tauri/src/repo.rs:120-148, 774-783, 789-810`
- **Constat** :
  - La table `rdv` ne dispose d'aucun index sur `debut`, `client_id` ou `statut`. La table `notes` ne possède pas d'index sur `client_id`.
  - Les fonctions `assert_no_overlap`, `rdv_list` et `rdv_dashboard` lisent l'intégralité des rendez-vous planifiés sans restriction de date en SQL, puis filtrent les plages temporelles en mémoire dans le code Rust.
- **Impact** : Balayage complet de table à chaque requête (`full table scan`). À mesure que l'historique du cabinet grandit (plusieurs centaines ou milliers de consultations), la mémoire et le temps CPU augmentent linéairement.
- **Correction proposée** :
  - Ajouter des index dans le schéma :
    ```sql
    CREATE INDEX IF NOT EXISTS idx_rdv_statut_debut ON rdv(statut, debut);
    CREATE INDEX IF NOT EXISTS idx_rdv_client ON rdv(client_id);
    CREATE INDEX IF NOT EXISTS idx_notes_client ON notes(client_id);
    ```
  - Appliquer les filtres de date directement dans la clause `WHERE` en SQL (`WHERE rdv.statut = 'planifie' AND rdv.debut >= ?1 AND rdv.debut < ?2`).
- **Effort** : M

### Problème 5 : Risque de perte de saisie des notes lors de la fermeture de l'application
- **Sévérité** : Majeur
- **Emplacement** : `src/routes/notes/+page.svelte:42-44` et `src/lib/components/RdvPanel.svelte:96-98`
- **Constat** : Les modifications de notes sont envoyées via un timer temporisé (400 ms). Lors de la destruction des composants Svelte (`onDestroy`), la promesse asynchrone `noteSave.flush()` est déclenchée sans attendre (`void`).
- **Impact** : Si l'utilisateur ferme la fenêtre immédiatement après avoir tapé un texte clinique, le processus de l'application se termine avant la persistance en base SQLite. Les dernières phrases écrites sont perdues sans notification.
- **Correction proposée** : Intercepter l'événement de fermeture de la fenêtre Tauri (via `onCloseRequested`) pour synchroniser tout enregistrement de note en attente avant d'autoriser la fermeture.
- **Effort** : M

### Problème 6 : Régénération systématique du PDF à chaque simple consultation
- **Sévérité** : Mineur
- **Emplacement** : `src-tauri/src/honoraires.rs:291-302`
- **Constat** : Lors de l'appel à `honoraires_ouvrir_path`, le fichier PDF est systématiquement réécrit sur le disque via `write_pdf`, même s'il existe déjà.
- **Impact** : Si le fichier PDF est ouvert et verrouillé par un lecteur externe ou si les droits en écriture sont restreints, l'ouverture échoue avec le message générique "Le PDF n'a pas pu être ouvert". La date de modification du fichier est également altérée à chaque consultation.
- **Correction proposée** :
```rust
pub fn honoraires_ouvrir_path(conn: &Connection, id: &str, pdf_root: &Path) -> Result<PathBuf, AppError> {
    let detail = honoraires_get(conn, id)?;
    let path = pdf_abs(pdf_root, &detail.honoraire.pdf_relatif);
    if !path.exists() {
        crate::honoraires_pdf::write_pdf(&detail, &path)?;
    }
    Ok(path)
}
```
- **Effort** : S

### Problème 7 : Double requête IPC lors de la navigation dans l'agenda
- **Sévérité** : Mineur
- **Emplacement** : `src/routes/agenda/+page.svelte:48-61, 82-100`
- **Constat** : Les fonctions `goToday`, `prev` et `next` mettent à jour `calendarValue` et appellent directement `loadRdvs()`. La modification de `calendarValue` réveille en parallèle l'$effect réactif qui rappelle également `loadRdvs()`.
- **Impact** : À chaque clic sur "Aujourd'hui", "Précédent" ou "Suivant", deux requêtes IPC concurrentes sont émises pour charger exactement les mêmes données.
- **Correction proposée** : Retirer l'appel explicite `loadRdvs()` des méthodes de boutons et laisser l'$effect gérer l'actualisation unique sur changement de date.
- **Effort** : S

### Problème 8 : Risque de saut de page incohérent sur le bloc totaux du PDF
- **Sévérité** : Mineur
- **Emplacement** : `src-tauri/src/honoraires_pdf.rs:260-285`
- **Constat** : La pagination vérifie la hauteur restante uniquement pour les lignes de séances. Les totaux HT, TVA et TTC sont imprimés avec `emit_x` sans contrôle d'espace restant.
- **Impact** : Si le tableau de séances arrive juste en bas de page, les totaux sont tracés en dessous de la marge basse (voire hors page), puis la mention "Arrêtée la présente facture..." passe seule sur la page suivante.
- **Correction proposée** : Vérifier la hauteur requise pour le bloc totaux + mentions légales (~45 mm) avant d'écrire la ligne de séparation des totaux, et déclencher un saut de page propre si l'espace est insuffisant.
- **Effort** : S

### Problème 9 : Présence de tirets cadratin / demi-cadratin dans l'interface
- **Sévérité** : Mineur
- **Emplacement** : `src/lib/components/RdvPanel.svelte:64` et `src/lib/format.ts:37`
- **Constat** : Des caractères Unicode demi-cadratin `–` (U+2013) sont utilisés pour formater l'intervalle horaire (`formatTime – endTime`) et la plage de semaine.
- **Impact** : Non-conformité avec la règle stricte du projet interdisant les tirets cadratins dans l'interface utilisateur.
- **Correction proposée** : Remplacer `–` par le tiret simple standard `-`.
- **Effort** : S

### Problème 10 : Écrasement des retours à la ligne des adresses dans le PDF
- **Sévérité** : Suggestion
- **Emplacement** : `src-tauri/src/honoraires_pdf.rs:343-363`
- **Constat** : La fonction `wrap` utilise `s.split_whitespace()`, fusionnant tous les retours à la ligne saisis par l'utilisateur en un seul bloc continu.
- **Impact** : Une adresse formatée sur plusieurs lignes (étage, rue, code postal, ville) apparaît aplatie sur une ligne continue dans le document PDF.
- **Correction proposée** : Découper le texte par ligne (`s.lines()`), puis appliquer le wrapping sur chaque ligne individuellement.
- **Effort** : S

### Problème 11 : Signature à 13 arguments sur la commande `clients_upsert`
- **Sévérité** : Suggestion
- **Emplacement** : `src-tauri/src/commands.rs:451-465`
- **Constat** : Clippy remonte un avertissement `clippy::too_many_arguments` (13 arguments passés individuellement au handler IPC).
- **Impact** : Rigidité du contrat IPC, risque d'inversion d'arguments optionnels de type chaîne et lisibilité dégradée.
- **Correction proposée** : Remplacer les 13 paramètres par une structure dédiée `ClientUpsertInput` dérivant `Deserialize`.
- **Effort** : S

### Problème 12 : Absence de tests d'intégration des composants d'interface
- **Sévérité** : Suggestion
- **Emplacement** : `tests/`
- **Constat** : Les tests frontend existants (34 tests) couvrent exclusivement des fonctions utilitaires pures. Aucun test ne valide les formulaires clients, les dialogues d'agenda ou la saisie de note.
- **Impact** : Risque de régression silencieuse sur le comportement réactif de l'UI lors de mises à jour de dépendances Svelte ou Bits UI.
- **Correction proposée** : Ajouter une suite de tests de composants pour les flux critiques (création de RDV, édition de client, émission d'honoraire).
- **Effort** : L

## 6. Les 5 actions prioritaires

1. **Supprimer le N+1 du menu contextuel des RDV (P2)** : Différer l'interrogation de l'état des honoraires au moment où le menu contextuel est ouvert (lazy-loading) au lieu de l'exécuter dans un `$effect` sur chaque créneau. C'est le premier goulot d'étranglement de l'application.
2. **Corriger le découpage UTF-8 de `mask_secret` (P1)** : Remplacer l'indexation par octets par une manipulation d'itérateurs de caractères pour éliminer tout risque de crash brutal au chargement des réglages.
3. **Persister la connexion SQLite et exécuter les migrations une seule fois (P3)** : Conserver le `Connection` sous `Mutex` dans le `State` Tauri et réserver l'exécution de `migrate` au `setup` initial.
4. **Sécuriser la fermeture de l'application pendant la saisie des notes (P5)** : Intercepter la demande de fermeture de fenêtre Tauri afin de garantir l'achèvement des écritures différées.
5. **Indexer les tables SQLite et filtrer par date en SQL (P4)** : Ajouter les index sur `rdv(statut, debut)` et `notes(client_id)`, et remplacer le filtrage en mémoire par une clause `WHERE` SQL.

## 7. Problèmes structurels transverses

- **Couplage excessif entre le cycle de vie de l'UI et les requêtes métier** : L'utilisation de `$effect` réactifs dans des composants individuels (comme les menus contextuels) pour exécuter des requêtes asynchrones en arrière-plan sans coordination globale multiplie les accès IPC. Une centralisation du chargement des données ou une stratégie de requêtes à la demande résoudrait ces congestions.
- **Modèle de persistance sans pool ni connexion résidente** : Le backend traite chaque commande IPC comme un script autonome qui ouvre la base, inspecte le schéma et referme la connexion. Dans une architecture Tauri, une instance de connexion protégée par un `Mutex` conservée pendant toute la durée de vie de l'application est le modèle standard.
- **Rôle du SQL sous-exploité** : La base de données SQLite est utilisée comme un simple stockage brut, laissant à la couche applicative Rust le soin d'effectuer les filtres de plages temporelles, les tris et les vérifications de chevauchement. Déplacer ces opérations vers des requêtes SQL indexées allégera le code Rust et stabilisera les performances à long terme.

## 8. Périmètre non audité

- **Exécution réelle de l'updater en environnement de production** : Le comportement complet de l'auto-mise à jour avec élévation de privilèges Polkit (`dpkg -i`) n'a pas pu être testé en situation réelle sans release active et sans environnement packagé.
- **Validation bout en bout des paiements Stripe réels** : Seule la génération de payload et la structure de l'appel HTTP ont été auditées ; aucune transaction réelle n'a été déclenchée sur les serveurs de Stripe.
